# Petrichor 项目计划

非规范性文档。English: [project-plan.en.md](project-plan.en.md)。

本文记录已有的开发与评估安排，不定义语言语义或支持版本保证。另见[规范](language-spec.zh.md)与[设计说明](design-notes.zh.md)。

## 当前状态与引擎版本

项目处于规范阶段，尚无语言实现。规范引用的引擎事实基于 Godot 提交 `469659e`（master，4.8-beta）核对，这是核对基线；支持的引擎版本尚未选择。

初始化、await、typed 容器等兼容性测试将固定到选定的评估引擎版本。

## 开发与评估

1. 收集公开反馈，收敛到可测试的最小核心。
2. 整理测试，考虑可复用测试集及其许可证；区分沿用的行为、有意改变的行为和新增能力，覆盖正向、负向、运行时和引擎集成情况。
3. 按收敛后的规范及测试实现树外模块。
4. 通过 AI 辅助迁移一个中型游戏来评估语言。Brotato 是规模和形态的参照，不是已经选定的源码项目。迁移以合法获得、许可适用的源码和素材为前提，也可以选择规模相当、可以授权的项目。

迁移评估记录标注与适配工作量、语言歧义、缺失的引擎契约、行为差异、性能瓶颈和调试成本。成功标准以规范和有效测试为准；偏差需要记录，不通过放宽类型或删除这些测试来掩盖。

## 工具与分发

实现语言、IR 和 JIT 的选择见设计说明；分发方式和编辑器集成深度尚未确定。

补全、断点和可执行程序导出可以分阶段验收，不必全部作为 alpha 的前提。第一版不计划专门扩展 `@tool` 或其他编辑器执行方式；能随集成自然接入的可以支持，其余延后。

其他已有的工具问题和提案包括：

- i32 等窄整数导出类型的范围提示，Inspector 编辑的是 64 位 int。
- 根据静态类型显示 enum 编码的调试器功能。
- 规范 §10 的诊断义务之外的修复建议和完整推断轨迹。
- 后续可考虑额外的浮点算术诊断；现行数值转换警告仍按规范 §7.3。
- enum 与拟议记录类型的编码分配开销 lint，特别是 `Array[enum]` 等容器中的分配。
- 向引擎上游贡献契约元数据。

## 兼容性核对

§8.2 的顺序是语言规则。与引擎行为对照，不会使它重新成为未规定的规则。场景属性注入和入树及其与继承的组合仍是 §8.3 的语言问题；未初始化非空 export 的读取遵循 §8.1，静态初始化遵循 §8.5。

已有兼容性工作还涵盖 await 恢复与重入、实例或信号源销毁、节点树状态变化、帧清理、跨语言异步值（§9）；typed 容器和外部读取检查（§12）；脚本、回调、属性及场景保存与加载（§13、§15）。

核对证据绑定到选定的引擎修订。引擎事实及源码位置记录在规范附录 A。
