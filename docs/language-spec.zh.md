# Petrichor 语言规范（草案）

**v0.1 · 2026-10-21 · 公开征求意见稿** · English: [language-spec.en.md](language-spec.en.md)

本文规定一门面向 Godot 的静态类型脚本语言。Petrichor 是项目代号。本草案有内容一致的中文和英文版本。

## 1. 概述

### 1.1 定位

- 面向 Godot 的静态类型脚本语言，支持类型推断。
- 复用 Godot core 的基础类型和基础设施。对本语言来说，它们是外部类型，其生命周期、复制方式和 ABI 契约由引擎规定。
- 复用 Godot 的语义，不等于兼容 GDScript 源码。
- 以 Godot 树外模块的形式交付，不以 GDExtension 兼容层或修改 core 为前提。终端用户写脚本不需要额外安装工具链。
- 不做热重载，也不做运行中的状态迁移；改完代码停止再重新运行是正常流程。

### 1.2 语义与实现

本规范规定程序是否合法、各处的类型和可观察行为，不要求采用特定的推断或执行算法。外部值的表示、相等比较和序列化遵循 §12；语言内 `==` 的规则见 §2.3。

设计理由和实现提案另见非规范性的[设计说明](design-notes.zh.md)。

### 1.3 文档约定

- 定义合法程序和所需行为的规则具有规范性。解释、设计理由、提案和计划不具有规范性；§15 和附录 B 单独标明这一点。
- 使用以下状态标记：
  - **【待定】**：语法或语义尚未规定。
  - **【已知限制】**：第一版不支持。限制程序合法性的规则仍具有规范性。
  - **【后续】**：延后的提案，不属于第一版契约。
- 除本规范已明确规定的形式外，代码示例中的具体语法拼法【待定】。
- “程序错误”指 §10 定义的运行时错误类别。
- 文中引用的引擎行为，均对照 Godot master（4.8-beta，提交 `469659e`）核对过，出处见附录 A。这是核对基线，不是支持版本声明；版本选择见[项目计划](project-plan.zh.md)。

## 2. 类型系统概览

1. 强静态类型，默认靠推断。推断不出类型时报错，不会悄悄退回 `Variant`。
2. `Variant` 只用于与引擎互操作，不是语言内的顶类型（§2.1）。
3. 方法调用和运算会形成能力约束；trait 用来给这些约束命名并复用（§4）。
4. 提供带载荷的命名 enum 和穷尽的模式匹配；Option 和 Result 也用同一套机制表达（§6）。
5. 条件表达式必须是 bool，没有普遍的“真值性”转换。
6. 单继承加覆盖，没有多继承。覆盖必须满足父方法的契约，不能缩窄父方法接受的参数。引擎回调的签名由引擎契约给出。
7. 用户不能自定义重载；保留默认参数、泛型和覆盖。引擎已有的多种调用形式由绑定层负责适配。
8. 表层语法沿用 Python／GDScript 风格的缩进和冒号。

### 2.1 Variant 类型

`Variant` 表示非 NIL 的引擎 Variant 值；可能为 NIL 的值使用 `Variant?`，即 `Option[Variant]`。它用于签名未知的 Callable、元数据、无类型容器和反射接口等互操作位置。

`Variant` 不是语言内的顶类型。语言值转换为 `Variant` 时，使用其类型的引擎编码（§12.1、§12.4），不保留静态类型：数值不保留源位宽，enum 成为其编码。`Variant` 不隐式转换为其他类型；从中取得语言值须显式转换，并按目标类型执行入口检查（§12.5、§12.6）；数值目标的 `T(v)` 数值转换按 §7.3 进行，不做范围检查。同一 `Variant` 值可能通过多个目标类型的检查，结果由目标类型决定。显式转换写作 `v as T`（§2.2）。

把 Object 引用转换为 `Variant`，不改变 Object 的继承体系、所有权和存活规则（§5）。将一个 `Variant` 值赋给另一个 `Variant`，复制的是其中的值，不会再增加一层容器。语言内异构值的需求留待后续的 dyn trait（见[设计说明](design-notes.zh.md#延后的语言提案)）。

### 2.2 is 与 as

`x as T` 检查 x 能否作为类型 T 使用，结果为 `Option[T]`。x 的静态类型须为对象类型、`Variant`，或它们的 Option；x 为 None 时结果为 None。其他源类型报编译错误：数值转换使用 `T(x)`（§7.3），enum 与其编码之间使用显式转换（§12.5）。第一版中 T 不能是泛型参数。

- **对象源，目标为类 T**：T 是源类型的子类时，在运行时检查实际对象（原生类及脚本类）是否属于 T，属于时得到 Some，否则得到 None；结果与原引用指向同一对象，所有权不变（§5.1）。T 是源类型本身或其父类时，结果总是 Some。T 与源类型没有继承关系时，报编译错误。源对象已被释放时，按失效访问报程序错误，不得 None（§6.5）。检查结果只在检查时成立，之后的访问仍检查存活和脚本身份（§6.5）。
- **`Variant` 源**：对 T 执行入口检查（§12.5、§12.6），通过时得到包含解码值的 Some，否则得到 None。例如值为 300 的 INT 经 `as u8` 得到 None，而数值转换 `u8(v)` 按 §7.3 得到 44。同一值可以通过多个目标类型的检查，例如 enum 编码既能 `as Array`，也可能 `as Cmd`。容器的元素类型不在转换时检查，读取元素时检查（§12.2）。

`x is T` 是 bool，等价于 `(x as T) != None`。它不收窄 x 的类型（§6.3）；需要使用转换后的值时，写作 `if var Some(e) = x as T:`。必须成功的转换写作 `(x as T)!`；`!` 直接作用于 `as` 表达式并失败时，诊断写明实际类型与期望类型。`as` 和 `is` 的运算符优先级【待定】。节点查找 `$X` 按期望类型检查节点的类（§6.5）。

```
@onready var sprite: Sprite2D = $Sprite2D        # 必须成功
var e = (scene.instantiate() as Enemy)!           # 必须成功
for body in get_overlapping_bodies():
    (body as Enemy)?.take_damage(1)               # 不是 Enemy 时跳过
    if var Some(p) = body as Player:
        p.hit()
var hp = get_meta("hp") as i32                    # i32?：非整数或越界时得 None
```

### 2.3 相等比较

`==` 的含义由两侧的静态类型决定，`!=` 是其否定。用户不能自定义 `==`（§2 第 7 条），类只按身份比较。

| 两侧类型 | 规则 |
|---|---|
| 数值 | 取 §7.5 的公共类型后比较；不存在公共类型时报编译错误，例如 `i64 == u64`、`i64 == f64`。浮点按 IEEE 754：NaN 不等于 NaN，0.0 等于 −0.0 |
| bool、String、StringName、core 值类型 | 两侧须为同一类型，使用引擎对该类型的比较；String 与 StringName 之间按内容比较（§7.7） |
| 对象 | 按身份比较；两侧类型须有继承关系，否则报编译错误。比较不是访问，不检查存活 |
| `Option[T]` | None 只等于 None；`Some(a) == Some(b)` 当且仅当 `a == b`。一侧为 `Option[T]`、另一侧为 T 时，将 T 包装为 Some 后比较 |
| 用户 enum | 分支相同，且各字段按其类型两两相等；纯无载荷的封闭 enum 比较成员，同号别名相等；开放 enum 比较整数值。enum 与整数比较报编译错误 |
| `Array[T]`、Dictionary | 使用引擎的容器比较（§12.2） |
| `Variant` | 使用引擎的 Variant 比较，INT 与 FLOAT 按数值比较；另一侧为其他类型时，先按 §12.1 编码再比较 |
| Callable、Signal、RID | 使用引擎的比较 |
| `weak[T]` | 不提供（§5.2） |

第一版只为数值和 String 提供 `<`、`<=`、`>`、`>=`；数值按 §7.5 的公共类型比较，不存在公共类型时报编译错误。

### 2.4 for 循环

`for x in e` 中的 e 可以是整数范围 `range(n)`、`range(a, b)`、`range(a, b, step)`，以及 `Array[T]`、`Dictionary[K, V]`、Packed 数组和 String。直接迭代整数（如 `for i in 5`）、浮点数或 `Variant` 是编译错误；`Variant` 须先转换，例如 `(v as Array)!`（§2.2）。【已知限制】第一版不支持用户自定义的迭代器协议。

| 迭代对象 | 循环变量的类型 |
|---|---|
| `range(…)` | 各参数按 §7.5 的公共类型；参数都是字面量时为 i32；不存在公共类型时报编译错误 |
| `Array[T]` | T；每次迭代读取元素时检查（§12.2） |
| `Dictionary[K, V]` | 键 K；值通过 `d[k]` 读取 |
| Packed 数组 | 引擎声明的元素类型，例如 PackedByteArray 为 u8，PackedInt32Array 为 i32，PackedFloat32Array 为 f32，PackedStringArray 为 String（附录 A） |
| String | String，每次一个字符 |

循环变量可以标注类型，例如 `for i: i64 in range(n)`。标注为 `range` 中的柔性字面量提供期望类型，其他参数在检查边界转换为标注的类型。迭代容器时，标注须为元素类型或其父类；下转型使用 `as`。

`range` 的参数只求值一次；step 为 0 是程序错误，step 可以为负。循环变量的递增不会在到达类型上限时溢出。

迭代期间修改容器遵循引擎行为，不产生未定义行为：Array 按下标迭代，每一步重新比较长度；Dictionary 迭代中删除当前键时，迭代结束（附录 A）。元素的读取仍按 §12.2 检查。每次迭代都使用新的循环变量，闭包按值捕获（§5.4）；对循环变量重新赋值不影响后续迭代。

## 3. 类型推断

推断由规则 R1–R7 定义。按这些规则，实现只需要做函数内的局部推断，再加上返回类型和成员的跨声明联合求解（§11）；不需要 let 多态、value restriction，也不需要匿名结构约束。

### R1 类型不由调用方决定

一个声明的类型，只由它自己的声明和函数体决定；如果存在互递归，就连同它所在的强连通分量一起决定。调用处不参与决定。

理由：如果从调用方反推，每多一处调用，函数的类型就可能变；而且 `call()`、编辑器里连接的信号、AnimationPlayer 的方法轨道这类调用方，静态分析根本看不见。

例外：lambda 的参数类型可以从创建处的期望类型得到。这只涉及局部，不违反 R1。

### R2 引擎能调用的都是单态，泛型必须显式声明

类方法、信号和成员属性都是引擎的入口：`call()`、`has_method`、信号连接、`call_deferred`、Tween、RPC 都按名字调用它们，参数是 Variant。所以这些入口必须有具体的签名。泛型必须在声明上写出类型参数，例如 `func max[T: Ord](a: T, b: T) -> T`。泛型函数不对引擎暴露。

理由有两点：

- 如果允许隐式泛化，同一个调用的静态路径和 `call()` 动态路径会算出不同结果：静态路径按 i32 实例化，而动态路径只有 64 位的 Variant int。
- 如果“是不是泛型”由推断决定，那么改动函数体可能让方法从 `has_method` 中消失，编辑器里已经连好的信号会在运行时找不到方法。

### R3 参数类型

参数类型按以下顺序确定：

1. 覆盖引擎虚函数的方法，参数类型取自引擎契约。
2. 否则，看参数**直接流向的、类型已知的位置**：作为实参传给类型已知的参数；赋值给类型已知的变量或成员；作为二元运算的一侧，且另一侧类型已知（此时取同一类型）；作为有返回类型标注的返回值。如果这些位置的类型全都相同，就取这个类型。
3. 否则要求标注。

有两种情况不能作为推断依据：

- **方法调用**：从 `x.hit()` 推不出 x 的类型。同名方法可能属于任何一个类，而新增一个类不应该改变已有代码的含义。
- **流向 Variant 或 Variant? 的位置**：`print(x)` 不会把 x 的类型确定为 `Variant`，否则就等于悄悄退回了动态类型。

```
func take_damage(amount):     # hp 是 i32，hp -= amount → amount: i32
    hp -= amount
func _on_body_entered(body):  # 只调用了 body.hit() → 要求标注
    body.hit()
```

### R4 局部变量

局部变量的类型在整个函数体范围内求解，求解完就固定下来。

- 如果初始化式给出了具体类型，类型就此确定，之后的赋值不会让它变宽（隐式转换按 §7.3 处理）。
- 初始化式中**开放的部分**，即柔性字面量（§7.2）和空容器的元素类型，按以下规则确定：
  1. **先看流入。** 如果有类型已知的值流入这个变量（赋值、复合赋值的右侧、往空容器里写入元素），类型取初始化式和所有流入值的无损公共类型。数值类型按 §7.5 的公共类型规则计算，没有公共类型时要求标注；非数值类型必须完全相同，不自动求共同父类。只由这个变量自身和柔性字面量组成的流入，不提供类型信息。
  2. **再看流向。** 如果没有这样的流入，就看变量流向哪些类型已知的位置（位置的种类同 R3）。这些位置的类型全部一致时，取这个类型；不一致或者根本没有时，柔性字面量取默认类型（整数 i32、浮点 f64），空容器的元素类型要求标注。
  3. 两个开放的局部变量之间互相赋值时，二者合为一组，共用同一个类型，按整组的流入和流向来确定。
  4. 结果与这些约束在代码中出现的先后顺序无关。
- 没有初始化式的局部变量必须有类型标注，类型即标注的类型，不隐式取默认值。在每个读取点，所有能到达该点的控制流路径上都必须已经赋值；判断时条件视为可真可假，常量 `true`／`false` 条件除外，穷尽的 match 视为覆盖所有情况。闭包不能捕获尚未确定赋值的局部变量。

```
var ratio = 0
ratio = position / length    # 流入的是 f64 → ratio: f64，字面量 0 也跟着取 f64

var t = 0.0
t += delta                   # 流入的是 f64 → t: f64
sprite.modulate.a = t        # 流向 f32：属于精度损失，默认不警告

var groups = 1
dispatch(list, x, y, groups) # 没有流入；流向一致都是 u32 → groups: u32
```

这几条规则的依据，是对真实 Godot 项目做的一次调查，详见[调查记录](surveys/literal-local-constraints.zh.md)。调查记录中的警告默认设置为调查当时的设置；现行默认设置见 §7.3。

**按源码顺序解析成员：** 在类型尚未确定的值上调用方法或访问成员时，只看源码中这个位置之前出现的约束，按上面的规则必须能确定类型，否则报错要求标注。如果此时是柔性字面量，而之前还没有任何约束，就当场取默认类型；之后再出现的约束只当作隐式转换处理。这是 R4 中唯一与先后顺序有关的情形。

```
var a = 1
a.abs()             # 之前没有约束 → a: i32
a = big_i64         # i64→i32，截断；可选整数转换损失警告

var items = []
items[0].hp -= 1    # 此时元素类型未知 → 报错，即使后面有 append(enemy)
items.append(enemy)
```

### R5 返回类型

返回类型从函数里所有的 return 推断。如果各分支的类型不同：

- 同一个 enum 的不同分支，合并为该 enum；
- 不同的数值类型，按 §7.5 合并为公共类型；
- 不同的类，不自动求共同父类，第一版直接报错要求标注。自动求出来的往往是 Node 或 Object，而且会随类层次的变化而变；
- 整数、字符串这类不同类型的返回分支，不会自动合成一个匿名的和类型。

### R6 成员和信号

成员变量的类型来自类型标注或初始化式。初始化为空容器的成员必须标注类型，不能从其他方法或其他文件里的用法反推，因为 Inspector、`get_property_list` 和其他文件的推断都需要先知道成员的类型。信号参数也必须标注，因为 emit 的地方就是调用方（见 R1）。信号的发射、连接和 await 规则见 §9。

### R7 推断出的签名就是接口

修改函数体，可能改变推断出的签名，从而让其他文件中的调用报错。这是推断式体验固有的代价。此时诊断信息必须同时给出：调用方期望的类型、被调方推断出的类型，以及决定这个类型的那一行源码。协程性同样属于推断出的签名（§9）：给函数加入 await 后，以值使用其调用的调用方会报错，诊断须指出使其成为协程的那一行 await。

### 3.8 隐式转换只在检查边界发生

隐式数值转换（§7.3）、字符串类型之间的隐式转换（§7.7）以及子类到父类的转换，只在检查边界发生：期望类型已知的赋值、实参和返回值，或者二元运算两侧都已经是具体类型的时候。如果遇到尚未确定的类型，就推迟到它确定以后再判断。

## 4. 泛型与 trait

- trait 显式地为能力约束命名。一个类型是否满足 trait 按结构判断：只要具备签名匹配的方法就算满足，不需要再声明一遍。
- 泛型函数是唯一的多态来源（R2）。在泛型函数内部，对类型参数的方法调用和运算，必须由 trait 约束或内建的运算约束覆盖；泛型代码中运算两侧必须同型（`T + T -> T`）。
- 第一版的 trait 只包含方法签名，只能用作泛型函数的约束；不支持默认方法、关联类型、泛型 trait 和 trait 对象。
- trait 不能用来引入字段注入、mixin 或多继承，也不改变 Node 的类型树。
- **泛型代码的语义必须与具体类型一致**，不能退化成 Variant 运算。例如 `add[T](a: T, b: T)` 以 i32 实例化时，必须按 32 位的运算和溢出规则执行；而 Variant int 是 64 位，结果会不一样。String 的写时复制、Ref 的引用计数等外部类型，复制和析构的方式也各不相同。
- 对每个具体实例化，trait 和内建运算约束在编译期解析到唯一实现。本规范不规定类型参数的表示或执行策略，另见非规范性的[设计说明](design-notes.zh.md#泛型与执行)。

## 5. 对象模型与生命周期

### 5.1 对象的种类

所有类的实例都是 Godot Object，上面挂着 ScriptInstance。没有写 extends 的类默认继承 RefCounted，这一点与 GDScript 一致；本语言的引用计数就是引擎的引用计数。按静态类型，值分为以下几种：

| 种类 | 静态类型 | 语义 |
|---|---|---|
| 拥有引用 | RefCounted 及其子类（包括 Resource，以及没写 extends 的类） | 强引用会延长对象的寿命；可以使用 `weak` |
| 句柄 | 不是 RefCounted 子类的类（如 Node），但不包括 Object 本身 | 引用不延长寿命，本质上是 ObjectID 加一次存活检查；`weak` 对它没有意义，不允许使用 |
| 由实际对象决定 | Object | 实际对象是 RefCounted 时持有强引用，否则就是句柄；可以使用 `weak` |
| 值 | 数值、bool、Vector2 等 core 值类型、String、enum | 赋值即复制（写时复制等优化由引擎契约实现） |

**所有权不会因为静态类型改变而丢失。** RefCounted 对象上转为 Object 后，仍然持有强引用；再下转回来也一样。这与 Variant 持有对象的方式一致。RefCounted 的父类只有 Object，所以 Object 是唯一需要看实际对象来决定语义的静态类型。泛型代码以 Object 实例化时，同样遵循这一所有权规则。

### 5.2 引用环与 Node 的生命周期

- 不引入追踪式 GC，也不要求 move 或借用标注。
- 引用环不会被自动回收。可以用弱的反向引用，或者在明确的生命周期操作里手动断开。不要依赖析构函数去断开那些本身就阻止析构发生的引用环。
- Node 的生命周期由引擎管理，本语言的引用不会延长它的寿命。

`weak[T]` 提供 `get() → Option[T]`：对象仍存活时返回 Some，已释放时返回 None。T 为 RefCounted 及其子类或 Object 时允许使用 weak；静态已知为 Node 等非 RefCounted 类型时不允许使用（§5.1）。

当实际对象是 RefCounted 时，成功取得的值持有强引用；绑定到局部变量后，该值按 §5.1 的规则延长对象寿命。当 T 为 Object、实际对象是 Node 等非 RefCounted 对象时，取得的值仍为句柄，不延长寿命，访问时仍检查存活。

一次 get 取得结果，再按 §6.3 用条件模式绑定取得对象，例如 `if var Some(p) = parent.get():`。先检查 weak、稍后另行取值不提供同一次取得的保证。该接口沿用引擎线程契约，不提供任意线程并发获取的安全保证；引用释放与线程边界见 §5.5。

`weak[T]` 是不可原地修改的值类型，默认值为空 weak，其 `get()` 返回 None（§8.4）。`weak[T]` 不能用于 `@export`，第一版也不提供 `==`。在引擎边界上，`weak[T]` 编码为引擎的 WeakRef 对象，空 weak 编码为不指向对象的 WeakRef（§12.3）；引擎每次读取 weak 成员得到的 WeakRef 不保证是同一个对象。`get()` 时目标存活但不是 T，是程序错误（§12.3）。

### 5.3 外部容器与写回

- Array 和 Dictionary 是共享引用。
- Packed*Array 在脚本变量之间按引用共享，但引擎内置的属性和方法返回的是副本。所以在 GDScript 里，`line.points.append(p)` 会悄无声息地不起作用。
- **写回规则：** 修改从属性上取得的值类型（包括调用会修改自身的方法）时，按“取出、修改、写回”执行。例如 `node.position.x += 1` 和 `line.points.append(p)` 都会把结果写回属性。一个方法是否修改自身，根据 builtin method 的 const 信息判断。

### 5.4 复制与闭包

- 赋值按类型复制值或共享引用（§5.1）；对象的浅复制、深复制须显式调用。
- 复制沿用各类型已有的 API，不另设统一的 copy／deepcopy 语法。Array、Dictionary、Resource、Node 等使用各自的 `duplicate` 类接口，具体复制范围、选项和共享行为由该接口的契约规定；不保证深复制整个对象图。
- 用户定义的 class 可以照常使用继承的复制接口，包括 Resource、Node 子类继承的 `duplicate`。没有合适接口时，由用户编写构造函数或复制方法，不自动生成复制操作。
- enum 是值类型，赋值复制其值；其中的引用载荷仍按其类型共享，不因 enum 的值复制而深复制。
- 闭包按值捕获当前的值；如果捕获的是引用类型，仍然和外部共享同一个对象。闭包不能重新绑定外部的局部变量。闭包造成的强引用环同样需要手动处理。

### 5.5 引用释放与线程边界

离开作用域、返回或因程序错误退出当前执行时，释放该退出所结束的持有关系中的强引用。实际对象是否销毁仍取决于其他引用和引擎契约。返回、被闭包捕获或存入其他位置的值继续按正常持有关系存活，不因原作用域退出而释放这些其他持有关系。await 挂起不是作用域退出，挂起执行所持有的引用仍按其生命周期保留。挂起的执行不对 self 持有强引用；需要在挂起期间保持 RefCounted 实例存活时，可将 self 绑定到局部变量，由挂起帧持有。挂起的执行被取消时（§9），释放其持有的引用，与作用域退出相同。

多个独立对象的析构先后不作规定。需要顺序时，程序须显式执行相应操作；不规定精确的成员析构顺序。以上清理规则适用于语言控制的执行退出，不保证进程崩溃或强制终止时完成清理。

Node 的释放及各引擎 API 的线程限制遵循引擎契约。使用 Variant 或持有强引用不使对象或操作自动成为线程安全。第一版不提供自有线程调度或自动跨线程释放机制。静态值清理仍须保证所依赖的脚本代码和运行时可用（§8.5）。

## 6. enum、Option 与可空性

### 6.1 enum

- enum 具有值语义。引擎边界上的编码见 §12.4，转换为 `Variant` 时使用同一编码。编码不改变其值语义。
- enum 的内部值表示不是其引擎编码。编码是可显式复制出的表示；从编码构造内部值须按目标类型校验（§12.5）。
- **enum 的值不能原地修改**，只能构造新值。载荷中的引用类型在复制 enum 时不做深拷贝。
- **【已知限制】第一版不支持递归 enum。** enum 的值布局中不能出现循环，经过 Option 等值类型形成的循环也算，例如 `enum Tree: Node(i32, Tree?, Tree?)`。出现循环时报编译错误，诊断会列出循环路径，并建议改用 class，或者经由 Array、Dictionary 递归。经由这些引用类型的递归是允许的，例如 `enum Json: …, Arr(Array[Json]), Obj(Dictionary[String, Json])`。

用户定义的 enum 和未标记为开放的导入 enum 都是封闭类型。合法值必须对应声明的分支；未声明整数不能作为合法 enum 值流通，穷尽匹配据此覆盖其全部可能分支。

导入的引擎 enum 中，带 bitfield 标记的 enum，以及经核实取值不限于具名成员的 enum（§7.6），是**开放 enum**：

- 值域为全部 i64 整数，编码为 INT；具名成员是该类型的常量。
- `E(n)` 接受任意可由 i64 表示的整数值，不检查具名成员；不提供 `try_from_int`。转换为整数沿用下述显式整数出口。
- match 必须有兜底分支，不做穷尽检查。
- 带 bitfield 标记的开放 enum 支持同一类型之间的 `|`、`&`、`^`、`~`，结果仍为该类型；不同类型之间不提供这些运算。
- 默认值为 0（§8.4）。

全部分支均无载荷的 enum 保留自身类型身份，并提供显式整数出口：以整数类型为目标调用 `T(value)`，先取得其 i64 整数编码，再按 §7.3 的整数转换规则转换。除开放 bitfield enum 的上述位运算外，算术、位组合、移位和掩码在整数类型中进行，不产生未声明的 enum 分支。出口不隐式缩窄，也不豁免常量范围规则。引擎边界的 INT 编码不使 enum 成为整数类型；转换为 `Variant` 得到该 INT 编码，取回封闭 enum 时检查具名成员（§12.5）。

整数反向进入封闭 enum 时必须验证它对应合法的具名成员。失败不能重新解释为 enum、产生未知分支或导致未定义行为。无载荷的封闭 enum E 提供 `E.try_from_int(n) → Option[E]`：n 对应合法成员时返回 Some，否则返回 None。检查式强转 `E(n) → E` 用于预期成功的转换，运行时非法值报程序错误。两者都按输入的原整数值验证，不先截断或回绕成另一个成员，也不接受非整数输入。`E(n)` 的已知非法常量可由既有编译期错误规则诊断；try 方法的非法常量正常返回 None，不因失败可预测而报编译错误。这两种形式不适用于有载荷 enum 或对象下转型。

纯无载荷 enum 的整数编码统一为 i64；这不改变普通无约束整数字面量默认 i32 的规则。只有纯无载荷 enum 有编号；含有带载荷分支的 enum 写显式编号是编译错误，因为其编码按名字标记（§12.4），也没有整数出口。纯无载荷的用户 enum 的首个成员未显式编号时为 0，其后未显式编号的成员取前一成员编号加 1。显式编号使用 `enum E: A, B = 4, C`，其中 A、B、C 的编号分别为 0、4、5。赋号表达式必须是编译期整数，并可由 i64 表示；默认递增超出 i64 范围时报编译错误，不回绕。导入引擎 enum 保留绑定记录的原编号。

同一 enum 中重复编号的名字是同一个值的别名，不是可区分的分支；用户和导入 enum 均遵循此规则。别名不增加值域或穷尽匹配所需的分支。反向转换成功时返回该值，不承诺恢复唯一的声明名。

### 6.2 `T?` 就是 `Option[T]`

`Option[T]` 有两个分支：`None` 表示空缺，`Some(T)` 包含一个 T 类型的值。`T?` 是 `Option[T]` 的简写。语言内部没有 `null` 值。

嵌套必须保留。对于 `first[T](a: Array[T]) -> T?`，当 `T = Enemy?` 时，数组为空（`None`）和首个元素为空缺（`Some(None)`）是不同的值；两者也都不同于 `Some(Some(enemy))`。

Option 具有值语义。其内部布局未作规定；引擎编码见 §12.4：`None` 编码为 NIL，载荷编码不含 NIL 时 `Some(x)` 直接使用 x 的编码。裸 NIL 不是合法的 `Variant` 值，因此 `Variant?` 用 NIL 表示 `None`，用 v 本身表示 `Some(v)`。

`Option[T]` 只能转换为 `Variant?`，不能转换为非空的 `Variant`。

### 6.3 条件模式绑定

第一版不做基于 None 检查的类型收窄：`x != None` 是普通的 bool 表达式，不改变 x 的类型。取得载荷使用条件模式绑定、`?.` 或 `!`（§6.4）。

成员、属性和容器元素的值可能被其他代码改变。应先把读取的值绑定到局部变量，再使用该局部值；即使外部代码随后改变原位置，使用的仍是绑定时的值。闭包按值捕获（§5.4），不能重新绑定外层局部变量。

条件模式绑定写作 `if var PATTERN = expr:`，PATTERN 使用 match 的模式，不为 Option 设置特殊的解包规则。右侧表达式只求值一次；模式匹配成功时，在成功分支的词法作用域内绑定模式变量，匹配失败时执行 else（如有）。绑定变量可以按已有 var 规则重新赋值。

例如 `if var Some(x) = target:` 匹配 Some 分支并绑定其载荷；`if var Ok(v) = result:` 和用户 enum 分支按相同规则处理。Some 模式只解开一层：target 为 `Some(None)` 时，x 绑定到内层 None。

可失败和不可失败的模式都允许，不要求模式必须可反驳，也不因其必定成功而增加警告。裸变量模式 `if var x = target:` 绑定整个值并必定成功，即使 target 为 None；它不隐式解包 Option，也不进行真值判断。此时 else 永远不执行，但仍接受正常的语法和类型检查；成功分支的词法作用域和右侧求值次数不变。

此形式不提供运行时 `if const`，也不规定一般解构赋值。第一版不提供带 else 的绑定声明，见[设计说明](design-notes.zh.md#延后的语言提案)。match 模式其余具体语法仍按 §1.3 的未定范围处理。

### 6.4 可空语法糖

- **后缀 `!`**：从 `Some` 中取出值；对 `None` 使用时报程序错误并给出位置。它只保证有值，不保证对象还活着。
- **`?.`**：可空链。接收者为 None 时，整条链短路，结果是可空类型。`?.` 是一个完整的记号；后缀 `?` 用于 Result 的错误传播（§10）。本语言没有 `?:` 三元运算符，所以不会产生歧义。
- `?.` 遇到已经释放的对象时，不会把它当作 None，而是照常报失效访问错误。

### 6.5 非空不等于存活

- 一个 Node 引用即使非空，对象也可能已经被释放，因此必须照常做失效访问检查。例如，同一个非空的局部 Node 变量跨过一次 await 之后，“非空”仍然成立，但“存活”就不一定了。
- 存活也不等于仍是该类。引擎和其他脚本可以替换对象的脚本：旧脚本实例随即被删除，对象本身照常存活（附录 A）。通过静态类型为本语言类 T 的引用访问成员或调用方法时，除存活外还检查对象当前的脚本实例属于 T 或其子类；不符时按失效访问报程序错误。self 同样适用：脚本被替换后，正在执行的方法访问 self 的成员时报错，方法本身仍可返回；实现须保证不访问被删除实例的存储。新脚本是 T 的子类时检查通过，访问的是按构造规则初始化的新实例。静态类型为引擎原生类的引用不受影响。本语言不拦截对 `script` 属性的写入（附录 A）。
- 引擎契约不确定时，先标记为可空，有了证据再补全本地的绑定描述。
- 外部的可变容器，不能因为扫描过一次就永久获得静态保证（容器的类型保证见 §12.2）。
- 外部值的空缺检查遵循 §6.3：先将读取的值绑定到局部变量，再用条件模式绑定取得载荷。
- `$X` 和 `%X` 是必须成功的节点查找。期望类型（§3.8）为 Node 的子类 T 时，找到的节点须属于 T；找不到节点或类不符都报程序错误。没有期望类型时，结果为 Node。允许缺失的查找使用绑定为返回 `Option[Node]` 的接口，需要子类时再用 `as` 转换（§2.2）。因此，`@onready var child = $Child` 和 `@onready var s: Sprite2D = $Sprite2D` 都不需要额外的 `!`。非空结果仍须检查存活。

## 7. 数值与字符串

### 7.1 类型

| 项目 | 规定 |
|---|---|
| 有符号整数 | i8、i16、i32、i64 |
| 无符号整数 | u8、u16、u32、u64 |
| 浮点数 | f32、f64 |
| int、float | 不是类型，不能用于类型标注；仅作转换构造器：`int(x)` 转换为 i32，`float(x)` 转换为 f64（§7.3） |
| 数值字面量类型后缀 | 第一版不提供；期望类型及无上下文默认类型见 §7.2 |
| i128、usize 等 | 暂不提供 |

第一版不提供整数或浮点字面量的类型后缀，包括 `u`、`l`、`ll`、位宽后缀及 `f`／`d`。需要指定数值类型时可使用类型标注；表达式中使用 `T(x)` 数值显式转换（§7.3）。科学计数法的指数标记 `e`／`E` 不是类型后缀，不受这项限制。

### 7.2 柔性字面量

- 整数字面量取另一个操作数的类型，或者期望类型；值放不下时报编译错误；完全没有约束时取 i32。
- 浮点字面量取期望类型；没有约束时取 f64。
- 整数字面量也可以取浮点类型，例如 `var v: f32 = 10`、`Vector2(1, 2)`。
- 普通字符串字面量同样是柔性字面量，见 §7.7。

例如在 `func f(x: u8): return x + 100` 中，100 取 u8，结果也是 u8；当 x ≥ 156 时会溢出，这是程序错误（§7.4）。在 `Time.get_ticks_msec() - 1000` 中，1000 取 u64。

### 7.3 数值转换

无损数值转换在检查边界（§3.8）自动进行。是否无损按源类型的完整取值范围判断，例如 i32→i64、u32→i64、i32→f64、f32→f64 都是无损转换。有损隐式转换也允许，但须满足下述常量规则。

显式数值转换写作 `T(x)`，其中 T 是目标数值类型，例如 `i64(x)`、`f32(x)`。另有转换构造器 `int(x)` 和 `float(x)`，分别等同 `i32(x)` 和 `f64(x)`；int、float 不是类型。x 的静态类型为 i64、u32、u64、enum 或 Variant 时，`int(x)` 报编译错误，须改写为 `i32(x)` 或 `i64(x)`；enum 的整数编码为 i64（§6.1）。GDScript 的 `int(x)` 是 64 位转换；这一限制避免迁移代码被无提示地截断。

目标类型为直接作为操作数的柔性字面量提供期望类型（§7.2）。因此 `u64(18446744073709551615)` 中的字面量直接取 u64，不先默认成 i32。已经确定类型的值按本节及 §7.5 的既有转换规则处理；显式转换不豁免常量越界错误。

```
var largest = u64(18446744073709551615) # u64，范围内
var invalid = u8(300)                  # 编译错误
```

对象下转型和 `Variant` 的检查式转换使用 `as`（§2.2）。其他转换形式【待定】。本节不规定非数值类型的 `T(x)` 构造。

#### 整数转换

将非常量整数 x 转换为 N 位整数类型时，令 r 为满足 `0 ≤ r < 2^N` 且 `r ≡ x (mod 2^N)` 的唯一整数。目标为无符号类型时，结果为 r。目标为有符号类型时，若 `r < 2^(N−1)`，结果为 r；否则结果为 `r − 2^N`。

因此，窄化丢弃高位，同宽的符号转换保留位模式。加宽时，有符号源做符号扩展，无符号源做零扩展，与目标是否有符号无关。即使损失值域，这些转换也有确定的结果，是合法的运行时操作，不受算术溢出检测设置影响。

| 源值与类型 | 目标 | 结果 |
|---|---|---|
| 300，i32 | u8 | 44 |
| −1，i8 | u8 | 255 |
| 255，u8 | i8 | −1 |
| −1，i8 | u16 | 65535 |
| 255，u8 | i16 | 255 |

表中描述的是非常量值的转换。整数常量超出目标范围时，隐式和显式转换都报编译错误；此错误不可关闭。范围内的常量保持原值，通过转换。

```
const limit: i32 = 300
var small: u8 = limit         # 编译错误
var small_cast = u8(limit)    # 编译错误

func narrow(x: i32) -> u8:
    return x                 # 有定义的转换；运行时 300 转为 44
```

常量传播确定操作数为单一常量值时，同样适用常量规则。`var` 声明本身不阻断传播。范围分析如果只表明运行时的值可能损失值域，并不能使该值成为常量，也不能据此报告这个错误。

编译器必须诊断越界的整数字面量，以及常量表达式中的越界整数转换。第一版可以尚不能完成其他常量传播，后续版本可以增强，包括跨声明或跨函数传播。未被诊断的常量错误仍然是错误，后续诊断可以拒绝它。漏诊既不产生未定义行为，也不允许优化器假设该转换不可达；如果执行到该转换，结果仍遵循上述整数转换规则。

#### Variant 中的数值

对 `Variant` 值执行数值转换 `T(v)` 时，INT 按 i64 取值，FLOAT 按 f64 取值，再应用本节及 §7.5 的数值转换规则，不要求目标类型匹配原始源位宽。u64 转换为 `Variant` 时按位传输为 INT（§12.1），因此 `u64(v)` 恢复原值。`T(v)` 不做入口检查的范围检查；需要范围检查时，按目标类型执行入口检查（§12.5、§12.6）。

例如，值为 1 的 i32 和 i64 转换为 `Variant` 后，都是同一个 INT。下例的 x 是运行时输入；当其值为 18446744073709551615 时，same 保持该值，signed 按整数转换规则为 −1：

```
func convert_number(x: u64):
    var value: Variant = x
    var same: u64 = u64(value)
    var signed: i64 = i64(value)
```

此例描述运行时转换，不是越界常量转换。常量传播确定操作数的值时，转换为 `Variant` 不能豁免常量规则。非数值的 `Variant` 不会仅因请求数值目标类型就变成数值，此时报程序错误。

#### 转换警告

| 警告类别 | 范围 | 默认 |
|---|---|---|
| 精度损失 | f64→f32；可能丢失精度的整数→浮点（如 i32→f32、i64→f64） | 关 |
| 整数转换损失 | 可能损失值域的整数窄化和符号变化 | 关 |
| 浮点转整数的值域损失 | 浮点→整数 | 开 |

各类警告可独立设为 off、warn 或 error，不影响不可关闭的常量错误。常量能被目标类型精确表示时，不报损失警告。显式转换表示接受相应损失，但不能豁免整数常量的范围规则。

引擎混用 f32 和 f64：`_process(delta)` 的参数是 double，Vector2 分量是 real_t（标准构建中为 float，见附录 A）。默认设置下，`position += velocity * delta` 不产生警告。浮点转换仍遵循 §7.5。

### 7.4 整数溢出

- **整数溢出是程序错误**，与数组越界、整数除零属于同一类。
- 运行时的溢出检测默认关闭。关闭时，溢出的结果是确定的：按位宽回绕（二进制补码），**不是未定义行为**。优化不能假设溢出不会发生，各种执行方式的结果必须一致；帧同步联机、回放等功能都依赖这种确定性。
- 结果虽然确定，溢出在语义上仍然是错误：同一个程序在开启检测时会报错；如果编译期能证明会溢出，就报编译错误。
- 显式回绕使用整数方法 `a.wrapping_add(b)`、`a.wrapping_sub(b)`、`a.wrapping_mul(b)`，分别执行加、减、乘，不新增 `&+` 运算符。结果保持接收者 a 的整数类型，按该类型位宽回绕；不通过公共类型选择改变接收者位宽。
- 柔性字面量参数取接收者类型。已确定类型的参数按已有调用转换规则转为接收者类型（§3.8、§7.3），不要求一律显式转换。常量参数超出目标类型范围仍报编译错误；显式回绕仅允许运算本身的溢出，常量求值和运行时溢出检测开启时也不因该溢出报错。例如 `u8(255).wrapping_add(1)` 得到 u8 的 0，而 `u8(255).wrapping_add(300)` 因参数越界报编译错误。
- **编译期能证明的溢出一律报错：** 只要能证明某个表达式每次求值都必然溢出，就报编译错误。
  - 所有实现都必须报告的最低范围：常量表达式求值时溢出，以及字面量超出目标类型的范围。
  - 超出最低范围的情形，随版本逐步增加识别能力，只增不减，每新增一类都加入一致性测试。因此升级编译器后，原本能编译的代码可能报错，这是在指出原本就错误的程序。
  - 证明只在函数内部进行。跨函数推出的溢出不作为编译错误，最多给警告；这样可以保持增量编译和诊断位置的稳定。
  - 不允许误报。只有每次求值都必然溢出才报错；“可能溢出”属于潜在风险警告，其触发条件【待定】，第一版可以一条都不报。
  - 同一版本中，编辑器诊断和导出构建必须使用同一个分析器。

### 7.5 混合运算、除法与边界情况

**混合运算：** 两边操作数的类型确定后，结果取能无损表示双方源类型完整值域的最小公共类型。例如 i32+i64→i64、i32+u32→i64、f32+f64→f64。不存在这样的类型时，例如 i64+u64，要求显式转换。

整数与浮点混算同样遵循无损公共类型规则，不另设浮点优先规则。柔性字面量先按 §7.2 根据上下文定型，再对确定的类型应用本规则。是否无损按源类型判断，不按某次求值中的具体值判断。检查边界允许的有损隐式转换（§7.3），不作为算术公共类型的选择依据。

| 操作数类型 | 公共类型 |
|---|---|
| i16 与 f32 | f32 |
| i32 与 f32 | f64 |
| i32 与 f64 | f64 |
| i64 与 f32 或 f64 | 不存在，要求显式转换 |
| u64 与 f32 或 f64 | 不存在，要求显式转换 |

**浮点算术：** f32、f64 的浮点算术、舍入和非有限结果遵循 IEEE 754。常量浮点算术使用相同规则，不因舍入或溢出到无穷大而套用 §7.4 的整数常量溢出错误，也不增加浮点溢出的运行时检查。浮点除零按 IEEE 754 处理：有限非零数除以零得到符号相应的无穷大，零除以零得到 NaN，不属于整数除零程序错误。

本节不增加浮点算术警告；额外浮点诊断留待后续。§7.3 已规定的数值转换警告及其配置保持不变。遵循 IEEE 754 不承诺各平台数学库逐位一致或 NaN 载荷稳定。浮点转整数仍使用下表的语言转换规则；饱和和 NaN 转零不是从 IEEE 754 算术规则推导出的要求。

| 情况 | 规定 |
|---|---|
| 整数 `/` | 向零截断；不提供 `//` |
| 整数除零（`/` 和 `%`） | 总是程序错误，不受溢出检测开关影响 |
| 整数 `%` 的符号 | 与被除数相同 |
| MIN / -1 | 属于溢出：检测开启时报错，关闭时结果为 MIN；MIN % -1 恒为 0 |
| 移位位数为负或不小于位宽 | 属于程序错误：检测开启时报错，关闭时位移数按位宽取非负余数；常量位移数越界时报编译错误 |
| 左移移出的位 | 丢弃，不算溢出，不受检测开关影响；有符号类型的结果按补码解释 |
| 右移 | 有符号类型为算术右移（符号扩展），无符号类型为逻辑右移；不提供 `>>>` |
| 浮点→整数（显式或隐式） | 超出范围时饱和到目标类型的上下限，NaN 转为 0 |

C++ 中越界的浮点→整数 `static_cast` 是未定义行为，本语言不沿用。此转换规则不改变上述浮点算术规则。

**移位的类型：** 移位不适用上述公共类型规则。结果的类型是左操作数的类型；右操作数可以是任意整数类型，两侧不求公共类型。左操作数为柔性字面量时取期望类型，没有期望类型时取 i32，不取右操作数的类型（§7.2 的例外）。例如 u8 的 `b << 4` 仍为 u8；`var m: i64 = 1 << 40` 合法，而 `var m = 1 << 40` 中的 1 取 i32，位移数越界，报编译错误。

### 7.6 引擎边界

- 不沿用 GDScript 默认的标量位宽。区分三种类型：语言中的语义类型、引擎 API 的语义类型，以及 Variant／ptrcall 实际使用的 ABI 槽位。
- 引擎 API 可用的标量类型信息取自 `MethodBind::get_argument_meta()`（返回 `GodotTypeInfo::Metadata`，其中包括 INT_IS_UINT64 等）；extension_api_dump 的 `meta` 字段使用同一信息。这不替代下述按实际接口契约进行的开放 enum 标记。
- 导入的 enum 按 §6.1 分为封闭和开放两类。带 bitfield 标记的 enum，即 ClassDB／GDType 枚举元数据带 bitfield 标记、属性和参数信息带 `PROPERTY_USAGE_CLASS_IS_BITFIELD` 的 enum，自动导入为开放 enum，例如 Control.SizeFlags 和 Mesh.ArrayFormat（附录 A）。其他 enum 若经核实的接口契约表明其取值不限于具名成员，在绑定描述中将该类型整体标记为开放，并记录接口位置及证据。例如 Key：`key_label` 可以是除控制字符外的任意 Unicode 字符，`get_*_with_modifiers` 返回叠加了修饰位的值（附录 A）。其余导入 enum 保持封闭。不将全部引擎 enum 擦除为整数，也不要求各调用者自行绕过绑定；组合数值和位模式按 core 接口契约往返，不错误拒绝合法组合或静默损失位。
- C++ 中不同 enum 类型之间的运算符重载不随绑定导入。例如 Key 与 KeyModifierMask 的组合须在整数域进行，再转换回开放 enum。ClassDB／GDType 枚举元数据保存名称、int64 数值和 bitfield 标记，不记录可恢复原始声明位宽的信息；不能从它自动推断原生 enum 位宽（核对 Godot `469659e0617345149cd1eaec2e643d61d130aa6a`：`core/object/gdtype.h:48-52`、`core/object/class_db.h:488-495`；附录 A）。
- 对静态已知的 u64 引擎 API 槽位，u64 与 Variant int 之间的 ABI 编码按位重新解释（§12.3），不属于 §7.3 的源码常量转换。u64 转换为 `Variant` 时使用同一位传输（§12.1）。一个现成的例子：RefCounted 对象的 ObjectID 第 63 位为 1，当作 u64 时 ≥ 2⁶³，经过 Variant 后变成负数。
- 原始无符号引擎编号若通过有符号位模式暴露，绑定按已核实的运输契约保留记录的编号和位模式，不擅自改成另一数值，也不据此引入 u64 enum 底层类型。
- 运行时的越界检查独立于溢出检测，默认开启。【已知限制】第一版不提供关闭越界检查的方法，也不提供 unsafe 模式。

### 7.7 字符串

普通字符串字面量 `"…"` 是柔性字面量，规则与 §7.2 的数值字面量相同：期望类型为 String、StringName 或 NodePath 时取该类型，并在编译期构造；在二元运算中取另一侧操作数的类型；没有约束时取 String。局部变量按 R4 确定类型，例如 `var action = "jump"` 只流向 StringName 参数时为 StringName。带前缀的 `&"…"` 固定为 StringName，`^"…"` 固定为 NodePath；`$X`、`%X` 中的路径是 NodePath（§6.5）。

在检查边界（§3.8），String 隐式转换为 StringName 或 NodePath，StringName 和 NodePath 隐式转换为 String，与 GDScript 允许的转换一致。从 String 构造 StringName 要在全局表中加锁查找（附录 A）；字面量在编译期构造，不产生这项运行时开销。

String 与 StringName 之间可以用 `==`、`!=` 按内容比较（§2.3）。`<`、`<=`、`>`、`>=` 只用于 String 之间，StringName 不提供大小比较。String 与 StringName 拼接的结果为 String。

```
Input.is_action_pressed("jump")        # 字面量取 StringName
var action = "jump"                    # 只流向 StringName 参数 → StringName
anim.play("attack_" + str(n))          # String 在检查边界转换为 StringName
get_node("UI/HealthBar")               # 字面量取 NodePath
```

## 8. 变量、常量与初始化

### 8.1 var 与 const

- 只用 var 和 const 两个关键字，不另设 let 或 mut。
- const 只接受常量表达式。没有“运行时初始化后冻结”这种常量，也没有 `@onready const` 或单独的冻结阶段。
- const 声明的类型由显式标注确定；没有标注时，由初始化表达式确定。剩余无约束的整数字面量默认 i32，浮点字面量默认 f64，并继续遵循 §7.1–§7.2 的数值类型及柔性字面量规则。使用位置不反推声明类型。
- 常量在使用位置遵循已有的转换和常量范围规则（§7.3）。固定类型不丢弃已知值，也不关闭常量传播。

```
const N = 1              # i32
const SCALE = 0.5        # f64
const SMALL_SCALE: f32 = 0.5 # 标注确定为 f32
const WIDE: i64 = 1      # 标注确定为 i64
```

- 成员、构造、场景注入和 `@onready` 都沿用 Godot 的生命周期，不引入面向用户的初始化状态类型。
- 非空成员必须从有效来源初始化；`None` 不是 T 类型的值。确实可能缺失的值使用 `T?`。

不写初始化器的声明按下表处理：

| 声明 | 不写初始化器时 |
|---|---|
| 成员、静态字段 | 须有类型标注（R6）。T 有默认值（§8.4）时取默认值，每个实例或类各自新建；否则处于未初始化状态，直到第一次赋值 |
| `@export` 成员 | 同成员 |
| `@onready` 成员 | 编译错误 |
| 局部变量 | 须有类型标注，并在读取前确定赋值（R4）；不隐式取默认值 |
| const | 编译错误 |

- 处于未初始化状态的成员，包括上表中没有默认值的成员和静态字段，以及初始化器尚未执行的 `@onready` 成员：能静态判定的非法读取报编译错误，其余情况在运行时检查，并给出写明成员名的诊断。
- 未初始化的成员可以在实例化后由创建者、场景注入或本类代码赋值，例如为未提供值的非空 `@export` 引用补齐。只要仍未初始化，每次读取都按前条规则检查；一次读取尝试不会永久关闭检查。不新增实例化完成时的全量扫描。
- 未初始化状态是单向的：成员一旦初始化，本语言代码和外部写入都不能使它回到未初始化。此状态不是语言内部的 null，也不是该类型的默认值；本语言没有表示它的值。外部向已初始化的非空成员显式写入 NIL，由非空入口检查拒绝（§12.6）。成功初始化可以记录状态，正常的外部值检查和对象存活检查仍然有效。
- 引擎和其他脚本经 `get` 读取处于未初始化状态的成员时，得到 NIL，不是程序错误；这包括未提供值的非空 export，以及初始化器尚未执行的 `@onready` 成员。前述读取检查只适用于本语言代码的读取。引擎写入 NIL 时，仍未初始化的成员保持未初始化；已初始化的非空成员拒绝该写入，值不变。因此，引擎复制节点或资源、调试器读取成员时，`set(name, get(name))` 不改变成员状态（附录 A）。

### 8.2 初始化顺序与规则

本语言沿用 GDScript 的初始化顺序：

- 构造时，先从基类到派生类执行所有普通成员的初始化器，再调用 `_init`。
- `@onready` 成员的初始化器在调用 `_ready` 时执行，早于用户写的 `_ready` 函数体，同样按从基类到派生类的顺序。

在此基础上规定：

1. **构造期的成员初始化器不能引用 self**：不能调用实例方法，也不能读取其他非 const 成员。这一条可以静态检查，它消除了“基类初始化器通过虚调用，读到派生类还没初始化的成员”这一整类问题。**`@onready` 初始化器例外**：它在节点就绪时才执行，可以引用 self，例如最常见的 `@onready var child = $Child`。
2. **Node 和 Resource 子类的 `_init` 必须能以零个参数调用。** 场景实例化、资源加载和 `duplicate()` 都会以零个参数调用 `_init`。违反时静态报错，或者在实例化时报错。
3. **每个 `@onready` 成员都有一个“已初始化”标志，包括类型有默认值的成员。** 检查的是“这个成员的初始化器是否已经执行完”，而不是“是否已经进入 `_ready`”。读取一个还没完成初始化的成员是程序错误，诊断信息要写明成员名和调用栈。这种情况无法完全靠静态分析排除，例如：
   - 子节点的 `_ready` 先于父节点执行。如果子节点同步发出一个信号，而父节点的处理函数读取了自己的 `@onready` 成员，这个成员此时还没有初始化。
   - 某个 `@onready` 初始化器调用的方法，读取了声明在它后面、还没初始化的另一个 `@onready` 成员。如果是初始化器直接读取后面声明的成员，可以静态报错。

### 8.5 静态初始化

静态初始化属于类／脚本的加载及依赖满足过程。同一份运行时类状态只初始化一次，不随每次实例化重跑。基类的静态初始化先完成，再按声明顺序初始化本类静态字段，最后执行本类的 `_static_init`。内嵌类遵循同样的依赖约束，不因其嵌套位置而无条件排在外层类之前或之后。

跨类读取静态值、调用静态方法或构造实例之前，目标类的静态初始化必须已经完成。纯类型引用和类型推断中的循环不构成初始化执行循环；只有实际执行的初始化依赖无法满足时才报程序错误，诊断包含依赖链。可静态判定的错误在编译时报出，其余在运行时报出；不以临时零值或其他未完成值代替结果，也不产生未定义行为。

本类初始化过程中，初始化器及其调用的本类内部代码可以读取按声明顺序已经完成初始化的本类字段；执行这些内部代码不要求本类整体已经完成。但不能经由其他类绕回尚未完成的本类、构造尚未完成初始化的目标类，或读取未完成字段来绕过完成约束。

有显式初始化器的字段，在其初始化器完成前不可读取，即使该字段是数字或 Option。没有初始化器的静态字段按 §8.1 处理：类型有默认值时，在其声明顺序位置完成默认初始化后即可读取（§8.4）；否则处于未初始化状态，直到第一次赋值，在此之前读取是程序错误，不构成初始化依赖失败。底层存储的准备不使字段成为已初始化。默认值也不保证资源句柄有效等业务前提。

声明初始化和底层默认存储准备都不调用字段 setter；后续普通赋值的 setter 规则不变。第一版静态初始化不能通过 await 挂起。

初始化失败时，类不能作为已完成初始化的类供正常使用；后续访问不能自动重试初始化及其副作用。已经发生的外部副作用不保证回滚。清理静态值期间，这些值所依赖的脚本代码及运行时必须仍然可用。这些规则不提供热重载或运行状态迁移。

### 8.6 属性：存储属性与计算属性

属性分为存储属性和计算属性，具体语法【待定】。setter 的参数类型为属性类型，返回 void；getter 返回属性类型。

| | 存储属性 | 计算属性 |
|---|---|---|
| 底层存储 | 有；按 §8.1 初始化，可以 `@export` | 没有；不能写初始化器，不能 `@export` |
| setter | 可选 | 可选；没有 setter 时只读 |
| getter | 不允许；读取总是直接读字段 | 必须有 |
| 引擎看到的属性 | 带 STORAGE；复制和存档只读写字段 | 不带 STORAGE，不被存档或复制；`get`、`set`、Tween 和 AnimationPlayer 可以使用 |

- **存储属性**：本语言代码和引擎的读取都直接读字段，不运行用户代码。写入经过 setter；在该属性自己的 setter 内部，赋值直接写字段。复合赋值 `hp += 1` 读字段后经 setter 写回；对值类型属性的局部修改（如 `pos.x += 1`）按 §5.3 的写回规则经 setter 写回。成员初始化器、`@onready` 初始化器和静态字段初始化器直接写入字段，不调用 setter（§8.5）。§8.1 关于未初始化成员的引擎读写规则适用于所有存储属性。
- **计算属性**：本语言代码和引擎的读取都调用 getter，写入都调用 setter，在类内部也是如此。getter、setter 内部不能引用该属性本身。只读的计算属性被本语言代码赋值时报编译错误，被引擎 `set` 写入时报程序错误。getter 读取其他未初始化成员时，按本语言代码的读取处理（§8.1）。
- 引擎 `set` 先按属性类型执行入口检查（§12.6），再调用 setter。setter 内部调用的其他方法再次给该属性赋值时，会再次进入 setter。
- setter、getter 不能是协程（§9）。需要在节点就绪后才施加的副作用，写作在 setter 中判断 `is_node_ready()`，并在 `_ready` 中统一施加一次；setter 中出现 await 时，诊断给出这一改写。

```
@export var color: Color:
    set(v):
        color = v
        if is_node_ready(): _apply_color()
func _ready():
    _apply_color()
```

需要惰性初始化或缓存时，使用私有的存储字段加计算属性。这一分法使引擎对存储数据的读取（复制、存档、调试器）不运行用户代码，代理和派生属性不留下无用的存储，并且可以声明只读属性。对真实项目的调查中，GDScript 代码需要手工改写的 getter 约为每千行 0.12 处，setter 中的 await 约为每千行 0.19 处（见[调查记录](surveys/property-accessors.zh.md)）。

## 9. await、信号与 Callable

- await 只做最小的接入，对接 Godot 的信号、计时器、帧事件和主循环，不另外实现执行器（executor）。挂起时的帧，以及局部变量的保存和恢复，由本语言负责。
- 生命周期、恢复顺序和可重入性尽量与 GDScript 保持一致；除下述实例销毁时与 GDScript 相同的取消外，不自行发明自动延迟（deferred）或取消机制。信号可能同步地恢复执行，不能假设一定要到下一帧才继续。
- 挂起的执行不对 self 持有强引用（§5.5）。所属实例被销毁时，它挂起的执行随之取消：等待中的信号连接断开，挂起帧持有的引用按 §5.5 释放，此后不再恢复，也不报错。这与 GDScript 一致（附录 A）。因此，等待另一实例上的协程时，若该实例被销毁，等待方会一直挂起，直到其自身所属的实例被销毁。节点退出场景树不等于销毁，挂起的执行不因此取消。
- 签名已知的函数、闭包和回调使用静态函数类型，参数和返回值都做静态检查。
- 引擎中签名未知的 Callable 保留擦除类型的形式。第一版通过绑定层使用 callv 调用；参数按绑定契约使用 `Variant` 或 `Variant?`。未知的结果类型为 `Variant?`，除非可靠契约排除了 NIL（§12.6）；Option 的空缺检查遵循 §6.3，取得 `Variant` 后按目标类型显式转换（§2.1）。
- **信号的类型。** 信号参数须标注类型（R6）；信号成员的静态类型是带这组参数类型的信号类型，语法【待定】。引擎可见的信号信息带有参数类型。
- **发射。** 经静态信号发射（如 `hit.emit(5, self)`）时，实参按参数类型静态检查，隐式转换只在检查边界发生（§3.8），并按参数类型编码后交给引擎（§12.1）。按名字发射（`emit_signal("hit", …)`）时类型已擦除，实参为 `Variant`，不做静态检查。引擎发射信号时不按声明检查实参类型（附录 A）。
- **连接。** 连接静态函数类型的 Callable（如 `hit.connect(on_hit)`）时，参数个数须相等，且每个信号参数的类型都能赋给对应的函数参数类型；函数参数可以是信号参数类型的父类。`bind`、`unbind` 的结果和擦除类型的 Callable 在调用时检查。引擎调用本语言的接收方时，实参按接收方的参数类型执行入口检查（§12.6）。
- **await 信号的结果。** 静态信号没有参数时，await 不产生值，使用其结果报编译错误。有一个参数时，结果为该参数类型的值；发射方传来的值不符合该类型时，在恢复处报入口检查错误。有多个参数时，第一版的 await 只能作为语句，不能使用其结果；语料调查中，使用这类结果的写法只出现一次，且来自参数未知的信号（见[调查记录](surveys/await-signal-results.zh.md)）。引擎类的信号按 ClassDB 的参数信息定型，Object 参数在契约不确定时可空（§6.5），例如 `await area.body_entered` 的结果为 `Node2D?`。参数未知的信号沿用 GDScript 的结果形状，结果类型为 `Variant?`：没有参数时为 None，一个参数时为 Some(该参数)，多个参数时为 Some(由各参数组成的 Array)（附录 A）。
- **协程。** 函数体中出现 await 的函数（包括 lambda）是协程。协程性由函数体推断，属于推断出的签名（R7）。
- **调用协程。** `await f()` 等待协程完成，得到其返回值。作为语句调用且不写 await 时，协程运行到第一次挂起，随后调用方继续执行，返回值被丢弃。在表达式位置使用协程调用的值而不写 await，是编译错误。
- **await 的操作数**只能是信号或协程调用；对其他表达式使用 await 是编译错误，包括 `Variant` 值。
- **覆盖。** 覆盖方法的协程性须与基类方法一致。基类方法返回 void 时例外，包括 `_ready`、`_process` 等引擎虚函数：覆盖方法可以是协程，经基类类型调用时按语句调用执行。返回值不是 void 的引擎虚函数，其覆盖方法不能是协程。
- **函数类型**记录协程性，语法【待定】。只有经协程函数类型调用时才能使用 await。返回 void 的协程可以转换为对应的非协程函数类型，调用时按语句调用执行，因此可以连接到信号；返回值不是 void 的协程不能这样转换。
- `_init`、`_static_init`、属性的 setter 和 getter 不能是协程；静态初始化不能挂起（§8.5）。
- **引擎调用协程。** 引擎或其他语言调用本语言的协程时，调用在协程第一次挂起时返回 NIL，返回值被丢弃。【已知限制】第一版不支持跨语言协程：其他语言不能等待本语言协程的结果，本语言也不能 await 其他语言的协程或异步值（见[设计说明](design-notes.zh.md#延后的语言提案)）。
- 【待定】节点的 owner 被销毁、节点退出场景树、信号源被销毁、挂起帧被释放等情况，都需要对照选定的评估引擎版本测试，必须避免重复恢复、内存泄漏和失效访问。
- 【后续】保留完整签名的可变参数泛型（参数包）。但不会因此引入一整套开放记录（row polymorphism）。

## 10. 错误与诊断

预期之内、可以处理的失败用 Result 作为返回值。Result 具有成功类型和错误类型：Ok(v) 包含成功值，Err(e) 包含错误值。

后缀 `?` 只用于 Result 表达式：

- 对 Ok(v)，表达式得到 v，继续求值。
- 对 Err(e)，立即从当前函数或闭包返回 Err(e)。

当前函数或闭包必须返回 Result，且错误类型与操作数相同；成功类型可以不同。错误类型必须一致，不做隐式错误类型转换。闭包内部的 `?` 从该闭包返回，不从包围它的函数返回。

Option 不能作为 `?` 的操作数。可空链使用独立的记号 `?.`（§6.4）。

- **程序错误**包括：数组越界；失效访问，包括对象已释放或脚本已被替换（§6.5）；读取未初始化的值；整数除零；非空断言失败；开启检测时的整数溢出和越界移位（§7.4–§7.5）；检查式 enum 转换失败（§6.1）；必须成功的 `$X` 查找失败（§6.5）；非数值 `Variant` 的数值转换（§7.3）；静态初始化依赖无法满足（§8.5）；编码超过深度上限（§12.4）；以及外部值检查失败（§12.3、§12.5–§12.6）。程序错误会产生运行时诊断和调用栈；脚本在哪里终止执行，由引擎调试器决定，不预设整个游戏必须退出。
- 诊断须标明源文件、位置和相关类型约束的因果链。
- 跨文件的错误不能只报一句“入口脚本加载失败”；类型冲突要给出两侧的类型和必要的来源位置（R7）。
- 编译失败时，不发布部分完成的签名或可执行产物。

## 11. 编译模型

递归、互递归和跨文件推断，按强连通分量（SCC）联合求解。分量由声明（函数或成员）组成，不以整个文件为单位。跨文件导出的签名可以推断，不强制每个公共函数都有标注。

声明的依赖包括根据推断出的接收者类型选定的方法。例如在 `func f(): return make_b().g()` 中，`make_b` 返回 B，由此确定对 `B.g` 的依赖。本规范不要求采用特定的依赖发现算法。

一个分量的联合推断全部成功后，才能向分量之外发布签名；失败时丢弃该分量的临时结果。不支持多态递归。引擎加载资源的顺序不将推断限制为各文件独立进行。

初始化循环与类型循环分别处理。const 值属于常量表达式，因此拒绝它们之间的循环。构造期的成员初始化器不能引用 self（§8.2）。跨对象的构造递归，例如 A 的成员初始化为 `B.new()`，而 B 的成员初始化为 `A.new()`，可能导致运行时栈溢出。

修改后不得继续使用过期的推断签名或可执行结果。增量编译不提供热重载，普通运行时调用永远不会触发推断。算法、协调方式和缓存策略另见非规范性的[设计说明](design-notes.zh.md#推断与增量编译)。

## 12. 引擎互操作：Variant 映射

运行时的类型保证按值所在的存储区分：

- **语言独占的存储**：局部变量、闭包捕获的值，以及解码得到的 enum 值及其字段槽位。值在进入时满足其类型，之后不再重复检查。
- **语言管理、外部可写入的存储**：本语言类的成员。引擎和其他脚本经 `set`、场景注入等入口写入时，按声明类型执行入口检查（§12.6）。
- **引擎管理的存储**：Array 与 Dictionary 的元素、引擎类的属性和方法返回值，以及其他脚本的成员。引擎和其他脚本可以绕过静态类型写入这些位置，因此每次读取并作为受信任类型使用时，都按目标类型检查当前值（§12.2、§12.5）。

一次检查成功只说明当时的值有效，不使该位置永久有效。对象引用无论位于哪类存储，访问时都检查存活；静态类型为本语言类时，还检查脚本身份（§6.5）。

### 12.1 值、表示与 ABI

Godot Variant 是引擎的带标记值容器。语言中的 `Variant` 是非 NIL 的 Variant 值，`Variant?` 还包含 NIL（§2.1）；绑定层自动将它们适配到引擎的 Variant 槽位。`Variant` 是互操作类型，不保存语言值的静态类型。

语言值隐式转换为 `Variant` 时，使用其类型的引擎编码：

| 语言类型 | 转换为 Variant 时的编码 |
|---|---|
| i8…i64、u8…u32 | INT，保留数值 |
| u64 | INT，按位重新解释（§12.3）；≥2⁶³ 的值显示为负数 |
| f32、f64 | FLOAT，保留数值 |
| enum | §12.4 的编码 |
| `Option[T]` | 只能转换为 `Variant?`：None 为 NIL，Some 按 §12.4 编码 |
| `weak[T]` | WeakRef 对象（§12.3） |
| 其他类型 | §12.3 的表示 |

不同类型的语言值转换为 `Variant` 后可能具有相同编码，例如 u64 的最大值与 i64 的 −1，或 enum 编码与同形的普通 Array；它们在引擎侧按 Variant 比较时相等，作为 Dictionary 键时也相同。

`Variant` 不隐式转换为其他类型。显式转换为类型 T 时，执行与引擎写入声明类型为 T 的位置相同的入口检查（§12.5、§12.6）；数值目标另有 §7.3 的 `T(v)` 数值转换。同一 `Variant` 值可以通过多个目标类型的检查，例如一个 Array 既可以按 Array 读取，也可能按某个 enum 解码；结果由目标类型决定。显式转换写作 `v as T`，结果为 `Option[T]`；必须成功时写作 `(v as T)!`（§2.2）。

GDScript、编辑器、Dictionary 的键和资源文件都能观察外部编码。以下规则按类型规定编码，不为每个值重新选择。以后改变已确立的外部编码属于破坏性变更。

### 12.2 容器

- **本语言的容器就是引擎的容器**：`Array[T]`、`Dictionary[K, V]` 就是引擎的 Array、Dictionary，在两边共享，不做复制。引擎能表达的元素类型，使用引擎的 typed 容器。
- 类型保证分两部分：本语言自己写入时做静态检查；**每次读取时都做运行时检查**。如果读到的值不符合 T，就是程序错误，诊断信息类似“第 3 个元素是 null，但元素类型是 Enemy（可能被外部代码写入）”。如果实现能证明数据只被本语言写过，可以省掉检查；这是优化，不改变语义。
- 理由：引擎那边可以写入任何值。引擎的 typed Array 允许 Object 元素为 null；`Array[i32]` 在引擎那边只能表示成 `Array[int]`。如果改用本语言自己的容器、跨边界时复制一份，引擎对它的修改本语言就看不到了，这违反了“Array 是共享引用”的约定。
- 只有 T 按 §8.4 具有默认值时，`Array[T].resize(n)` 才可用，并为每个新增元素独立创建默认值；否则须使用 `resize(n, fill)`。显式 fill 遵循既有值／引用共享规则，不自动深复制。本语言不会把引擎原始 `Array::resize` 留下的 null Object 槽位当作非空 T 值接受（附录 A）。
- 容器的 `==` 使用引擎的比较：逐个元素比较，元素的 Variant 类型须相同，浮点元素按 IEEE 754 比较；Vector2 等 core 值类型元素和浮点 Packed 数组中的 NaN 分量则视为相等（附录 A）。因此容器比较可能与元素类型自身的 `==` 不同：两个含 NaN 分量的 Vector2 单独比较时不等，作为 Array 元素比较时相等。
- Dictionary 键的等价规则不同于 `==`：NaN 键彼此相同，INT 与 FLOAT 键不同，String 与 StringName 键相同（附录 A）。有类型的 `Dictionary[K, V]` 中所有键的编码类型相同；键类型为 `Variant` 时，1 与 1.0 是不同的键，尽管 `1 == 1.0` 为真。

### 12.3 类型映射表

本表规定声明目标类型对应的外部表示。u64 一行的位传输同样用于 u64 转换为 `Variant`（§12.1）。读回检查按目标类型校验外部表示，与对 `Variant` 值执行的 `T(v)` 数值转换（§7.3）不同。

| 语言类型 | 在 Variant 中的表示 | 读回时的检查 |
|---|---|---|
| i8…i64、u8…u32 | int | 值在范围内 |
| u64 | int，按位重新解释 | 不检查（≥2⁶³ 的值显示为负数，与引擎处理 ObjectID 的方式一致） |
| f32、f64 | float | f32 需要舍入，属于精度损失 |
| core 值类型（Vector2、String 等） | 同名类型 | 类型匹配 |
| 非空的 Object 类 T | Object | 非空，且类匹配 |
| `weak[T]` | WeakRef 对象；空 weak 为不指向对象的 WeakRef | 须为 WeakRef；目标存活时须是 T；`get()` 时再检查目标类 |
| enum（包括 Option） | 见 §12.4 | 完整解码，见 §12.5 |
| `Variant` | 任意非 NIL 值；语言值按 §12.1 编码 | 拒绝 NIL |
| `Variant?` | None 为 NIL；Some(v) 为 v | NIL 得 None；否则得 Some |
| 函数类型 | Callable | 本语言创建的 Callable 校验签名；其他来源的在每次调用时检查 |
| `Array[T]`、`Dictionary[K, V]` | Array、Dictionary | 读取时逐个元素检查 |

### 12.4 enum 的映射

本节规定 enum 类型面向引擎的编码。每个 enum 类型只有一种编码，按类型确定，不随具体值或外层上下文改变；转换为 `Variant` 时使用同一编码。

1. **纯无载荷 enum**：所有分支都无载荷时，编码为 INT，编号和别名规则见 §6.1。仅含一个分支的 enum 同样如此，例如 `enum Only: One` 的 One 编码为 0，不使用 NIL。解码为封闭 enum 时必须检查具名成员；开放 enum（§6.1）同样编码为 INT，解码时接受任意整数。
2. **Option[T]**：None 编码为 NIL。T 不是 Option 类型时，`Some(x)` 编码为 x 的编码；T 是 Option 类型时，`Some(x)` 编码为只读 Array `[&"Option.Some", x 的编码]`，以区分各层 None。
3. **其他 enum**：至少一个分支带载荷时，每个分支都编码为只读 Array `[&"Enum.Variant", 字段1, 字段2, …]`，无载荷分支编码为 `[&"Enum.Variant"]`。开头的 StringName 记录 enum 名和分支名，不包含类型参数：`Result[i32, String]` 和 `Result[f64, String]` 的 Ok 都使用 `&"Result.Ok"`，类型参数由目标静态类型补足。各字段递归使用其类型的编码。

在本语言的类型中，只有 Option 类型的编码包含 NIL，因此第 2 条只需判断 T 是否为 Option 类型。这里不做按载荷位置的布局优化。

```
enum Mode: Easy, Hard = 4                 # Easy→0  Hard→4
enum Cmd: Stop, Move(Vector3), Hit(Node, i32)
# Stop→[&"Cmd.Stop"]  Move→[&"Cmd.Move", v]  Hit→[&"Cmd.Hit", node, 5]
enum Hp: Dead, Alive(i32)                 # Dead→[&"Hp.Dead"]  Alive→[&"Hp.Alive", 5]
```

Option 的值是 `None` 和 `Some`，不含语言内部的 null 值。原始引擎 null 由绑定和读取检查处理（§12.5–§12.6）。

| 类型 | `None` | `Some(…)` |
|---|---|---|
| `i32?` | NIL | `Some(5)` → `5` |
| `Enemy?` | NIL | 对象本身 |
| `Cmd?`（上例的 Cmd） | NIL | `Some(Cmd.Stop)` → `[&"Cmd.Stop"]`；`Some(Cmd.Move(v))` → `[&"Cmd.Move", v]` |
| `Variant?` | NIL | `Some(v)` → v |
| `i32??` | NIL | `Some(None)` → `[&"Option.Some", NIL]`；`Some(Some(5))` → `[&"Option.Some", 5]` |
| `Variant??` | NIL | `Some(None)` → `[&"Option.Some", NIL]`；`Some(Some(v))` → `[&"Option.Some", v]` |

示例中的 NIL 是引擎编码，不是语言值。例如，`i32???` 的 `Some(Some(None))` 编码为 `[&"Option.Some", [&"Option.Some", NIL]]`。不同层的 `None` 互相区分，不得折叠。

**编码与身份：**

本语言生成的编码 Array 是只读的。Object 在 `==` 比较和作为 Dictionary 键时按身份比较；Array 按内容比较、计算哈希，并可直接序列化（附录 A）。在保持值语义的前提下可以复用只读编码；这不把编码规定为 enum 的内部值表示（§12.5）。不做位打包：Variant 只有一个类型标记，复制时仅保留具体类型的值，不保留数据区的空余字节（附录 A）。

编码不携带来源证明。同形的普通 Array 按目标 enum 解码时，与本语言生成的编码不可区分；没有目标类型时，编码 Array 只是 Array（§12.5）。引擎复制或序列化编码后，结果可能不再只读（附录 A），解码因此不检查只读状态。

依赖自动编号的纯无载荷 enum 调整成员顺序后，存档含义可能改变；按名字标记的编码在分支改名后会改变。给纯无载荷 enum 增加带载荷的分支，会使其全部分支的编码从 INT 变为按名字标记的 Array；已有存档和引擎侧按整数使用该 enum 的位置都会受影响。

**深度：** 编码如果会超过引擎递归上限（`MAX_RECURSION`，目前为 100，见附录 A），就是程序错误；解码遵守同一上限。这保证本语言的编码器不构造超限编码，不保证外部代码以后不能加深共享的 Array 或 Dictionary。后续读取和对象访问仍须进行正常检查（§12.2、§12.5）；构造时的保证不验证外部将来写入的内容。

### 12.5 读回与解码

每当外部可变位置的内容作为受信任类型的值进入语言时，都要检查。对一个位置检查成功，不代表该地址永久有效；再次读取引擎管理的属性或容器元素时，须检查其当前值（§12）。

读取为 `Variant` 时，NIL 是程序错误；读取为 `Variant?` 时，NIL 得到 `None`，非 NIL 值 v 得到 `Some(v)`。其他目标类型按以下规则检查：

- 纯无载荷 enum：须为 INT；目标为封闭 enum 时须对应其具名成员，开放 enum 接受任意 INT。
- `Option[T]`：NIL 得到 None。T 不是 Option 类型时，其他值按 T 解码，得到 Some；T 是 Option 类型时，须为长度为 2、开头为 `&"Option.Some"` 的 Array，第二个元素按 T 解码。
- 其他 enum：须为 Array；开头的 StringName 须指明目标 enum 的一个分支；长度须为该分支字段数加一；每个字段按其类型解码。嵌套 enum 递归解码。不检查只读状态。
- 其他类型：遵循 §12.3 的检查。

enum 与其编码之间可以显式转换：编码复制出表示；从 `Variant` 或 Array 构造 enum 须按目标 enum 类型执行上述解码。目标类型提供名义类型和所需的泛型实参。

标记说明编码所属的类型，不证明构造来源。合法的同形普通 Array 也可经显式转换构造 enum，不需要 Array 身份登记或不可伪造的来源证明。没有目标类型时，Array 不会仅因形状相同而被当作 enum。enum 与编码之间显式转换的具体 API 和持久化版本兼容协议【待定】。从 `Variant` 按目标 enum 解码也可以写作 `v as E`（§2.2）。

校验成功后，按目标类型构造独立的 enum 分支和字段槽位，不能把可变编码槽位直接作为受信任 enum 存储。随后修改输入 Array 的标记或字段槽位，不改变已构造 enum 的分支或字段槽位；无需冻结用户的输入 Array。字段中原本具有引用共享语义的对象和容器仍然共享，不要求整个对象图深复制。嵌套的 enum 值同样按其值语义构造；其中的引用载荷继续共享。

特别是，复制 Variant 只隔离值槽，不复制它所引用的 Array 或 Dictionary 的内容。因此，检查后的 `Variant` 副本并不保证共享容器元素有效，每次读取仍遵循 §12.2。编码 Array 可能被外部修改，每次解码都重新检查；仅复制其 Variant 槽位并不能使它成为受信任的值。非空 Object 值仍须遵守 §6.5 的存活检查。

本语言生成只读编码，在保持值语义的前提下可以复用。收到外部编码不代表它的共享内容以后不会变化。

### 12.6 绑定契约与入口转换

引擎 API 的 Variant 只有在可靠绑定契约排除 NIL 时，才映射为 `Variant`；否则映射为 `Variant?`。参数、返回值和属性均遵循此规则。绑定层自动完成编码和检查；普通调用不要求在源码中转换为原始 Variant 类型。

本语言的类实例是 Godot Object，因此 GDScript 和引擎代码能绕过静态类型，例如 `node.call("take_damage", "hello")`、`node.set("hp", 1 << 40)`、场景属性值、AnimationPlayer、Tween，或在 Inspector 中清空导出的引用。

每个传入的 Variant 都按声明的目标类型解码并检查（§12.3、§12.5），包括 callp 参数、`set`、信号回调、场景反序列化和 Callable 调用。类型不符、外部整数越界、非空位置缺值，均为程序错误。例外是向仍处于未初始化状态的成员写入 NIL：该成员保持未初始化（§8.1）。这是外部表示的检查，不是 §7.3 中语言值的整数到整数转换，不会悄悄截断。外部 Variant INT 的值为 300，直接读为 u8 时报错；对值为 300 的 `Variant` 显式执行 `u8(v)` 时，按 §7.3 得到 44。不能把直接的外部读取隐式绕经 `Variant` 数值转换，以跳过目标类型的范围或类型检查。

外部代码把 NIL 写入引擎管理的位置（§12）后：该位置暴露为 `Variant?` 时，下次读取为 `None`；暴露为 `Variant` 时，下次读取检查失败。外部代码修改别名容器时同样如此。本语言类的成员在写入时检查，类型为 `Variant` 的成员拒绝 NIL 写入。

## 14. 第一版范围与待定问题

第一版包含互操作用的 `Variant`、`Variant?` 和外部读取检查（§2.1、§12）。常量传播不完备不放宽常量错误规则（§7.3）。

### 14.1 已知限制

- 没有 dyn trait。trait 只包含方法签名，只能用作泛型约束（§4）。需要对不同类型的对象做鸭子类型式的处理时（例如遍历 `get_overlapping_bodies()` 并调用 `take_damage`），须用 `as` 取得所需具体类型（§2.2），或者用擦除类型的 `call()`。
- 没有语言内的顶类型。`Variant` 只用于互操作，不保存语言值的静态类型（§2.1）。
- 不支持递归 enum（§6.1）；用户不能声明开放 enum（§6.1）。
- 不做基于 None 检查的类型收窄，也不提供带 else 的绑定声明（§6.3）。
- 不同类的返回分支不合并为共同父类（R5）；不支持多态递归（§11）。
- `weak[T]` 不能用于 `@export`，也不提供 `==`（§5.2）。
- 静态初始化不能通过 await 挂起（§8.5）。
- 多参数信号的 await 结果不可使用（§9）。
- 不支持用户自定义的迭代器协议（§2.4）。
- setter、getter 不能是协程（§8.6）。
- 不支持跨语言协程：其他语言不能等待本语言协程的结果，本语言也不能 await 其他语言的协程或异步值（§9）。
- 不提供整数或浮点字面量的类型后缀（§7.1）。
- 泛型函数不对引擎暴露（R2）。
- 不提供关闭越界检查的方法，也没有 unsafe 模式（§7.6）。
- 不支持热重载，也不做运行中的状态迁移。

### 14.2 语言待定问题

- enum 的其余语法，trait、泛型、match 模式其余形式和其他转换形式的具体语法，以及 `as`／`is` 的运算符优先级（§1.3、§2.2、§6.3、§7.3）。
- 潜在整数溢出警告的触发条件（§7.4）。
- 场景属性注入、入树顺序及其与继承的组合（§8.3）。
- §9 列出的 await 生命周期边界。
- enum 与其编码之间显式转换的 API 和持久化版本兼容协议（§12.5）。

延后的语言提案见非规范性的[设计说明](design-notes.zh.md#延后的语言提案)。引擎版本选择、工具与分发见[项目计划](project-plan.zh.md)。

## 15. 一致性检查清单（非规范性）

本清单列举前述规则的检查实例，不增加语言要求。

| 领域 | 检查内容 |
|---|---|
| 推断 | 参数类型由流向推断；只有方法调用时要求标注；流向 Variant 或 Variant? 不算依据；局部变量先看流入、再看流向，结果与约束的顺序无关；方法调用处就地确定柔性字面量的类型；空容器成员要求标注；不同类的分支不求共同父类 |

## 附录 B：考虑过但没有采用的方案（非规范性）

本附录记录设计理由；语言规则以所引用章节为准。

| 方案 | 没有采用的原因 |
|---|---|
| 默认借用、显式 move，或放入容器时自动 move | 脚本场景下标注负担太重；改为共享引用，外部类型服从引擎契约 |
| 追踪式 GC | 改为引用计数、弱引用和手动断环 |
| `weak[T]` 编码为目标的 ObjectID 整数 | GDScript 只看到整数，看不出它是弱引用，也不能调用 `get_ref`；改为引擎的 WeakRef（§5.2、§12.3） |
| 普通引用自动让 Node 保持存活 | Node 的生命周期由引擎管理；句柄不延长寿命 |
| 禁止替换本语言对象的脚本 | 直接调用的 `set_script()` 没有否决钩子；脚本实例只能拦截经 `Object::set` 的路径，无法完全禁止（§6.5） |
| 拦截经 `set("script", …)` 的脚本替换 | 直接调用的 `set_script()` 无法拦截，脚本身份检查仍然必要；拦截只会去掉运行时检查器替换脚本的调试能力（§6.5） |
| 只检查存活、不检查脚本身份 | 脚本被替换后，访问会读到已删除的实例，产生未定义行为（§6.5） |
| 以 HM 作为推断路线，合法时隐式泛化普通函数 | 与“引擎可见的入口”冲突（R2）；改为先定语义（R1–R7），泛型必须显式声明 |
| 从调用方反推函数类型 | 函数类型会随着新增调用而改变，而且动态调用方看不见（R1） |
| 局部变量的多个约束不一致时直接报错（类 Rust） | 在调查语料中，这些冲突没有识别出 bug；R4 采用先看流入、再看流向（见调查记录及其局限） |
| 局部变量的类型只由初始化式决定（类 Swift、Kotlin、C#） | `var r = 0` 之后再赋值一个 double，会被截断成 0（R4，见调查记录） |
| 不写初始化器的局部变量隐式取默认值（类 GDScript） | 局部变量的控制流对编译器可见，确定赋值能发现遗漏的赋值，也允许非空类型的局部变量先声明后赋值（R4） |
| 类型有默认值的 `@onready` 成员在初始化器执行前读到默认值（类 GDScript） | 与 §8.5“有显式初始化器的字段在初始化器完成前不可读取”一致；读到默认值会掩盖初始化顺序错误（§8.2） |
| 没有默认值的成员一律必须写初始化器 | 在 `_init` 中赋值、在 `_ready` 中赋值和静态单例这些常见写法都得改用 `T?`；改为推广 §8.1 的未初始化状态 |
| 抽象的 int，沿着调用链再决定位宽 | 改为一整套定宽类型，没有约束时默认 i32 |
| 默认使用 f32 | 默认 f64；指定 f32 使用类型标注或数值显式转换，不使用类型后缀 |
| int 作为 i32 的类型别名 | GDScript 和引擎中的 int 是 64 位，沿用该名字会使迁移代码静默截断；int 不是类型，`int(x)` 拒绝 i64、u32、u64、enum 和 Variant 源（§7.1、§7.3） |
| 有损隐式转换统一报一种警告 | 精度损失、整数转换损失、浮点转整数的值域损失分别配置；整数转换默认静默截断（§7.3） |

| 允许 setter、getter 为协程（如 setter 中的 `await ready`） | 赋值背后出现异步，副作用的施加顺序取决于信号连接；改写为就绪后施加是机械的，以后可以兼容放宽（§8.6） |
| 类内部访问属性时绕过 setter（Godot 3 的 setget） | GDScript 4 已改为经过 setter，迁移代码依赖现行行为（§8.6） |
| 初始化时调用 setter | setter 可能读取尚未初始化的其他成员，与 §8.2 的目的相反，也与 GDScript 不一致（§8.6） |
| 用显式标记声明协程（如 `async func`） | 增加标注负担，与 GDScript 不一致；协程性可以从函数体推断（§9） |
| 覆盖时允许任意改变协程性（类 GDScript） | 调用方无法静态知道是否需要 await，返回值类型也不可靠（§9、附录 A） |
| 多参数信号的 await 结果为 `Array[Variant]`（类 GDScript） | 类型信息全部丢失，与签名已知的回调使用静态类型不一致（§9）；按参数解构的绑定见设计说明 |
| 连接时要求函数参数类型与信号参数类型完全相同 | 比允许父类参数更严，但没有带来安全上的好处（§9） |
| 挂起的执行持有 RefCounted 的 self | 等待的信号若永不触发，对象会一直泄漏；与 GDScript 不一致（§9） |
| 实例销毁后，在恢复挂起的执行时报错 | GDScript 在实例析构时断开等待并取消挂起的执行；常见的先 await、后 `queue_free` 写法会误报（§9） |
| 热重载与运行中的状态迁移 | 不做 |
