# 调查：脚本成员在哪里被使用

**2026-10-24** · 关联：[设计决定](../decisions.zh.md) §4 封装与命名、§9 语法 · English: [member-visibility.en.md](member-visibility.en.md)

## 问题

成员默认私有，对外公开的成员用 `pub` 标出（设计决定 §4）。要定两件事：`pub` 会写得多频繁，据此选关键字还是注解；不写 `pub` 的成员要不要让子类看到。

## 语料

与[跨分支重复调查](cross-branch-duplication.zh.md)相同：20 个仓库，固定提交，第一方代码的判定规则也相同（`cross-branch-duplication/gdcorpus.py`）。第一方代码共 203,720 行（不计空行和注释行），其中 12 个游戏仓库 70,646 行。

## 方法

- **成员**：第一方脚本中顶层的 `func`、`var`、`signal` 和 `const`，包括静态成员。不计对引擎虚函数的覆盖。子孙脚本中同名的重新声明（覆盖）只在根声明处计一次。
- **按名字匹配，不做类型解析。** 名字在仓库的第一方脚本中只有一个根声明、又不是引擎成员名的成员才分类，其余记为“无法判定”。
- **分类**：
  - 外部使用：在声明它的脚本及其子孙以外的第一方脚本中出现 `.名字`；
  - 只被子类使用：不是外部使用，名字出现在子孙脚本中，形式可以是调用、读写或覆盖；
  - 只在本文件使用：以上都不是；
  - 场景连接：第一方 `.tscn` 的信号连接以它为方法名的函数。这是引擎按名字访问，单独计。
- **外部写入**：对外部使用的 `var`，若其他脚本中 `.名字` 后接赋值运算符，则记为外部写入。

## 结果

| | 全部 | 游戏 |
|---|---|---|
| 第一方代码行 | 203,720 | 70,646 |
| 外部使用 | 4,597 | 2,129 |
| 只被子类使用 | 354 | 124 |
| 只在本文件使用 | 13,471 | 5,614 |
| 无法判定 | 9,429 | 3,714 |
| 场景连接 | 1,961 | 400 |
| 外部使用占可判定成员的比例 | 25.0% | 27.1% |
| 外部使用，每千行 | 22.6 | 30.1 |
| 只被子类使用占跨文件使用的比例 | 7.2% | 5.5% |

按成员种类（全部仓库）：

| | 外部使用 | 只被子类使用 | 只在本文件使用 | 无法判定 | 场景连接 |
|---|---|---|---|---|---|
| `func` | 2,518 | 232 | 6,430 | 3,824 | 1,961 |
| `var` | 1,332 | 107 | 5,136 | 4,526 | 0 |
| `signal` | 338 | 5 | 119 | 283 | 0 |
| `const` | 409 | 10 | 1,786 | 796 | 0 |

- 只被子类使用的 354 个成员中，85 个被子类覆盖，269 个只被调用或读写。其中 144 个名字以 `_` 开头，也就是作者按 GDScript 惯例当作私有的。
- 在有子类的脚本中，外部使用的成员有 690 个，只被子类使用的 354 个。
- 外部使用的 1,332 个 `var` 中，528 个被其他脚本写入，804 个只被读取。
- 各仓库的数字和全部“只被子类使用”的成员见 `member-visibility/results/vis.txt`。

## 局限

- 无法判定的成员（9,429 个）比外部使用的成员还多，因为 `speed`、`health` 一类常见的名字往往在几个无关的脚本中各自声明。它们的分布可能与可判定的成员不同。因此每千行 22.6 个只是 `pub` 数量的下限。
- `.名字` 可能指向另一个对象上的同名成员。引擎成员名和多处声明的名字已经排除，剩余的误差没有度量。
- 以字符串访问的成员（`call("m")`、`connect("s", ...)`、`get("x")`）没有计入外部使用。
- 只统计顶层成员，内部类的成员不计。

## 对设计的影响

- `pub` 每千行至少写 22 个（游戏 30 个），所以用关键字，不用注解。
- 只被子类使用的成员占跨文件使用的 7.2%（游戏 5.5%）。第一版因此不设子类可见的一级，这些成员标为 `pub`。覆盖非 `pub` 成员是编译错误，以后加入这一级不会破坏已有代码。
  - 后续：[第二次纸面迁移](paper-migration-2.zh.md)中这一比例为 28%，因为本调查把 `type`、`update_stat` 一类常见名字归为无法判定。设计据此改为子类可以访问不带 `pub` 的成员（[设计决定](../decisions.zh.md) §4）。
