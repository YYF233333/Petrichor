# Petrichor 设计说明

非规范性文档。English: [design-notes.en.md](design-notes.en.md)。

本文汇集设计理由和实现提案。程序合法性与可观察行为由[语言规范](language-spec.zh.md)规定。

## 设计目标

项目希望减少类型和内存管理标注，同时明确赋值、共享、转换、失效和错误的含义。规范先规定语义，再选择算法。引擎能观察到的表示属于语言契约。

设计倾向于选择以后可以兼容放宽的限制。尚无明确需求的能力延后处理，不预先为其优化。

## 泛型与执行

当前执行方案以 typed IR 解释器起步，JIT 是后续可能的执行方式。实现语言、IR、JIT 后端和分发选择尚未确定。

泛型实现草案为每个类型参数传入运行时类型描述符，其中包含大小、复制、析构操作和 trait 方法表，以便共享一份泛型代码。以 Object 实例化的描述符将遵循规范 §5.1 的所有权规则。

通过描述符间接调用，是执行编译期约束所选实现的一种方式；IR 层单态化、JIT 特化是备选或后续优化。这份草案不将描述符规定为语言语义，也不意味着已经选定实现方式。

## 推断与增量编译

一种依赖发现方案是在推断时按需请求其他声明的签名。在 `func f(): return make_b().g()` 中，推出 `make_b` 返回 B 后，即可发现对 `B.g` 的依赖。

声明可以标记为“推断中”。请求到达这种声明时形成回边，可用 Tarjan 风格的栈合并相关声明，形成强连通分量（SCC）。分量完成后发布结果，失败则丢弃其临时结果。

模块协调器草案负责联合推断，不受引擎逐个加载和校验资源的顺序限制。这一路线不要求引擎新增联合编译接口，也不要求修改 core。

增量实现可以维护依赖、反向依赖和缓存。初期实现可以保守地重新编译整个项目；接口不变时，可以复用调用方已有结果。这些属于实现策略；规范 §11 要求结果有效、原子发布，不规定使用栈、协调器或缓存。

## 静态初始化的设计依据

规范 §8.5 要求读取已完成的值，不能满足执行依赖时报告错误。这个契约不规定调度器或初始化状态机的实现，也不允许用临时默认值掩盖依赖循环。

以下依据来自上游问题报告和代码变更审阅，不是本地复现记录，也不表示这些问题仍存在于选定的评估版本：

- [#104161](https://github.com/godotengine/godot/issues/104161) 和 [#82141](https://github.com/godotengine/godot/issues/82141) 报告内嵌类静态值或实例初始化早于所需静态初始化的情况。因此，嵌套结构不代替执行依赖约束。
- [#104588](https://github.com/godotengine/godot/issues/104588) 报告资源加载与静态初始化循环产生不一致的解析错误。类型依赖与初始化执行依赖须分开处理。
- [#77098](https://github.com/godotengine/godot/issues/77098) 报告静态字段初始化中的重复 setter 调用。声明初始化不调用 setter。
- [#105667](https://github.com/godotengine/godot/issues/105667) 报告热重载执行初始化副作用后又恢复旧静态值。第一版不支持热重载；失败后的普通访问也不自动重试初始化。
- [PR #120976](https://github.com/godotengine/godot/pull/120976) 于 2026-07-13 合并，处理静态持有 lambda、挂起函数及脚本运行时退出清理的生命周期问题。清理值时所依赖的代码和运行时仍须可用；规范不照搬该 PR 的清理遍次。

## 延后的语言提案

以下提案不属于第一版契约。

- 值类型记录（`struct`）。已有提案沿用规范 §12.4 中含载荷 enum 的规则：记录编码为按名字标记的 Array `[&"Name", 字段…]`，单字段记录也不例外。容器内的可变字段按“取出、修改、写回”处理。以后若改用引擎的原生表示，需要迁移存档格式。
- 使用 Swift 风格的显式 `indirect` 标注支持递归 enum，在声明处表明分配。第一版仍不支持递归值布局。
- 带 else 的绑定声明，类似 Rust 的 let-else 和 Swift 的 guard let，用于提前退出写法：匹配成功时，模式变量在当前块的剩余部分有效；匹配失败时执行 else 块，且 else 块必须以 return、break 或 continue 结束。第一版不提供，提前退出写成嵌套的条件模式绑定（规范 §6.3）。基于 None 检查的流敏感收窄也可以以后兼容地加入。
- 静态排除成员在赋值前被读取，例如 Swift 式的两阶段初始化：构造函数为所有存储成员赋值之前，不允许调用方法或让 self 逃逸。第一版改用未初始化状态的运行时检查（规范 §8.1）。
- dyn trait，用于语言内的异构值；默认 trait 方法、关联类型；保留完整签名的参数包；对引擎不可见的函数进行隐式泛化。
- 语言内的顶类型。以后如有需要，可以作为新类型（例如 `any`）加入，不改变 `Variant` 的语义。其动态盒子使用与规范 §12.4 编码不同的保留标记，使 enum 编码与盒子可以区分。

工具、兼容性核对和评估安排见[项目计划](project-plan.zh.md)。
